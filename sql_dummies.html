LEARNING NOTES / SQL INJECTION

When data becomes a query.

SQL injection can occur when an application builds a database query by mixing untrusted input with SQL code. The result can be unauthorized access to or changes in data.

Use only applications you own or are authorized to test.

THE CORE IDEA

Separate code from data.

01 / RISK

Unsafe query construction

Concatenating user input into a SQL statement can let that input alter the query's meaning. A database error may be a clue, but its absence does not prove safety.

02 / DEFENSE

Parameterized queries

Prepared statements define the SQL structure first and bind input as data. This is the primary defense recommended by OWASP.

03 / DEPTH

Limit database privileges

Give the application account only the database permissions it needs. This can limit the damage if a separate flaw exists.
