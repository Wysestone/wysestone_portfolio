LEARNING NOTES / WEB SECURITY

Web security testing, made approachable.

A short introduction to questions I use when learning how to assess a web application. These notes are a starting point, not a substitute for the full OWASP Web Security Testing Guide.

Practice only on applications you own or are authorized to test.

A STARTING CHECKLIST

What to examine

01 / AUTHENTICATION

Who can sign in?

Check whether invalid credentials are rejected, account recovery behaves as intended, and rate limits or other protections respond to repeated attempts.

02 / AUTHORIZATION

What can each user access?

With test accounts at different permission levels, check whether the server denies access to another user's data or privileged functions.

03 / INPUT & OUTPUT

How is untrusted data handled?

Test inputs in a safe lab. A response should handle data in its proper context; relying only on input rejection is insufficient.

04 / SESSIONS

Does logout end access?

After logout, try a new request to a protected resource. A cached page alone does not prove an active server-side session.

05 / ERRORS

What does failure reveal?

Check whether error responses expose stack traces, internal paths, or other details that users do not need.

06 / TRANSPORT

Is traffic protected?

Check that sensitive pages use HTTPS and that an insecure connection cannot expose credentials or session data.
